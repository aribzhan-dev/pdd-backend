# pdd_backend

FastAPI-сервис платформы ПДД: аккаунты и роли, каталог вопросов, тестовые
сессии, которые переживают перезагрузку страницы.

Интерфейс живёт в отдельном репозитории — `pdd_frontend`.

## Стек

PostgreSQL 14+ · SQLAlchemy 2.0 (async, asyncpg) · Alembic · Pydantic v2 ·
PyJWT · bcrypt · pytest

## Структура

Каждый слой знает только тот, что ниже: `router → service → repository → model`.

```
app/
├── main.py               сборка приложения: CORS, роутеры, статика
├── core/                 config, engine/session, security, time, ошибки
├── enums/                role, category, student_status, quiz, language
├── models/               таблицы SQLAlchemy, по файлу на сущность
├── schemas/              Pydantic, по домену
├── repositories/         единственный слой, который пишет SQL
├── services/             бизнес-правила и права доступа
└── api/
    ├── deps.py           сессия, текущий пользователь, проверки ролей
    ├── errors.py         доменная ошибка → HTTP-ответ
    └── v1/routers/       auth, managers, students, content, quiz
scripts/
└── create_admin.py       первый администратор и сброс его пароля
```

## Роли

Идентификаторы в коде английские, всё видимое пользователю — русское.

| Роль | Права |
|---|---|
| `admin` | Управляет менеджерами; создаёт, редактирует и **удаляет** студентов |
| `manager` | Создаёт и редактирует студентов; **не может** удалять их и трогать менеджеров |
| `student` | Проходит тесты, смотрит свою историю |

Регистрации нет. Первый администратор создаётся из терминала, остальные
аккаунты выдаёт персонал: ИИН и пароль назначаются вручную и один раз
показываются, чтобы передать студенту.

## Доступ студента

Студенту выдаётся срок доступа. После его окончания вход закрывается, но
аккаунт и вся история остаются в базе со статусом `Доступ истёк`.

## Тестовые сессии

Сессия, порядок вопросов и каждый ответ хранятся в базе, поэтому:

* `GET /quiz/active` восстанавливает прохождение после перезагрузки — вместе с
  тем, где были ошибки, и сколько осталось времени;
* экзамен ограничен 40 минутами, режим обучения — нет;
* завершить можно после первого же ответа, вопросы без ответа считаются
  неверными.

## Медиа

`MEDIA_SERVE_LOCAL` решает, куда указывают ссылки на видео:

| Значение | Ссылка |
|---|---|
| `true` (разработка) | `/media/media/videos/situations/q_31_1000.mp4` |
| `false` (продакшн) | `https://otan-shymkent.kz/media/videos/situations/q_31_1000.mp4` |

В продакшне сервер не хранит видео вообще. Экранирование в двух режимах
разное — имена файлов в локальном хранилище буквально содержат `%` — поэтому
построение URL вынесено в `services/media_url.py` и покрыто тестами.

## Разработка

```bash
docker compose up -d                        # PostgreSQL на :55432
cp .env.example .env                        # SECRET_KEY; MEDIA_SERVE_LOCAL=true
alembic upgrade head
python3 -m scripts.create_admin --iin <12 цифр> --password <пароль>
uvicorn app.main:app --reload
```

Docker здесь — просто удобный способ поднять базу локально. На сервере
PostgreSQL работает нативно, см. [DEPLOY.md](DEPLOY.md).

Документация API: <http://localhost:8000/docs>

## Миграции

```bash
alembic revision --autogenerate -m "что изменилось"
alembic upgrade head
```

`alembic/env.py` берёт строку подключения из `core/config.py`, так что второго
источника настроек нет.

## Тесты

```bash
python3 -m pytest
```

Идут на SQLite в памяти — ни база, ни сервер для них не нужны.
